# Grus boot 2022.11.0 release notes

## 版本号规则

从此版本之后，grus版本命名规则有了变化，具体为：

`年`.`jdk主版本号`.`grus版本号`

所以java11的第一个版本号为`2022.11.0`。很多特性，两个版本会同步更新。

对java11的支持，会持续到其生命周期结束，即`2023.9`。此后，会强制要求大家升级java17。

## Rabbitmq升级

Rabbitmq消息队列sdk全新升级，老的api全部删除。具体查看[Rabbitmq介绍](../framework/mq/rabbitmq.md)

## 安全

!!! attention

    如果应用是web，默认禁用TLSv1.2以下的协议。

如果需要打开，使用配置`grus.web.disableOldSslProtocol=false`

## 兼容问题

- 原先二级缓存`CacheConfig.localRedis()`改为`CacheConfig.l2()`
- jackson升级后，蛇形转换的策略命名变更，即`spring.jackson.property-naming-strategy=CAMEL_CASE_TO_LOWER_CASE_WITH_UNDERSCORES`废弃，使用`spring.jackson.property-naming-strategy=SNAKE_CASE`

## 健康检查

新版本不再依赖我们编写的isLive健康检查，而使用springboot提供的默认健康检查探针。
在应用启动时，会注入以下的参数：

```properties
--management.server.port=8181
--management.endpoints.web.exposure.include=* 
--management.endpoint.health.probes.enabled=true 
--management.endpoint.health.show-details=always 
--management.endpoint.health.group.readiness.include=* 
--management.endpoint.health.group.readiness.show-details=always 
--management.endpoint.health.group.liveness.include=* 
--management.endpoint.health.group.liveness.show-details=always 
```

k8s会使用以下的请求来验证健康状况:

```shell
curl http://localhost:8181/actuator/health/readiness
curl http://localhost:8181/actuator/health/liveness
```

!!! attention

    springboot的健康检查，会额外检查数据库连接池状态和redis连接池状态。
    也就是说：如果数据库、redis连接不上或者挂了，那么程序的健康检查也失败了。
    程序会陷入重启状态，直到依赖恢复。
    此时访问服务，会出现服务不可用提示。
