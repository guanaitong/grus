# Grus 2023

## 影响

先讲下springboot3.0的重大改变：

1. 最大支持java17
2. 从Java EE切换到Jakarta EE。包空间从`javax.*`移动到`jakarta.*`
3. 新增了[声明式HttpClient](https://docs.spring.io/spring-framework/docs/current/reference/html/integration.html#rest-http-interface)
4. 支持native images。可以将springboot程序通过`GraalVM`打包成一个二进制程序。`GraalVM`本身是不支持反射的，而SpringBoot是通过编译时生成代码来解决这一问题。此特性我们暂且无法使用。主要有两点：
   1. 此特性是beta
   2. `GraalVM`开源版本只支持**Serial GC**，而**G1 GC**是商业版本。**Serial GC**由于是串行单线程机制，任何的垃圾回收都会stop the world，肯定无法用于我们生产环境。[Memory Management at Image Run Time (graalvm.org)](https://www.graalvm.org/22.0/reference-manual/native-image/MemoryManagement/)

对我们影响最大的是第二点，以及它对整个生态的影响。它需要我们使用的所有依赖javax的库，都完成迁移。包括grus和第三方库。其中，grus的升级改代码即可，而第三方只有等维护者解决。

我们使用到的javax包主要为：

| Java EE模块      | Jakarta EE模块     |
| ---------------- | ------------------ |
| javax.validation | jakarta.validation |
| javax.servlet    | jakarta.servlet    |

以下是第三方库的清单：

| name             | starter-name                          | 是否计划支持SB3.0 | 是否已经支持SB3.0      |
| ---------------- | ------------------------------------- | ----------------- | ---------------------- |
| mybatis          | mybatis-spring-boot-starter           | 是                | 已经支持（3.0.1）      |
| sentinel         | spring-cloud-starter-alibaba-sentinel | 是                | 暂未（2022.0.0.0-RC1） |
| springboot admin | spring-boot-admin-starter-client      | 是                | 暂未（3.0.0-M8）       |
| velocity         | alibaba-boot-starter-velocity         | 不支持            | 不支持                 |

grus的影响：

| name           | Java EE模块      | Jakarta EE模块     |
| -------------- | ---------------- | ------------------ |
| grus-servlet   | javax.servlet    | jakarta.servlet    |
| grus-redis     | javax.servlet    | jakarta.servlet    |
| grus-generator | javax.servlet    | jakarta.servlet    |
| grus-core      | javax.validation | jakarta.validation |

agg的影响：agg依赖grus构建，它属于业务层，由于业务应用将来会在新老的框架上都有，agg需要支持新老两个版本。列表主要为：

| name                 |
| -------------------- |
| ciicgat-agg-passport |

在Spring提供新的httpclient以及之前的webflux httpclient的基础上，原来的[SpringCloud Openfeign](https://spring.io/projects/spring-cloud-openfeign)慢慢进入停止更新维护阶段。而feign之前是整个Spring微服务体系非常核心的一块。针对此，在Grus2023上，要同时支持新的httpclient。

举例，老的写法：

```java
@Headers("Content-Type: application/x-www-form-urlencoded")
public interface MemberIdService {

    /**
     * 根据memberId获取member
     *
     * @param id
     * @return
     */
    @RequestLine("POST /member/get")
    Member getMemberById(@Param("id") Integer id);
}
```

新的写法：

```java
@HttpExchange(accept = "application/vnd.github.v3+json")
public interface MemberIdService {

    @PostExchange
    Member getMemberById(@RequestParam Integer id);

    @PostExchange
    Mono<Member> getMemberById(@RequestParam Integer id); //响应式编程方法
}
```

可以看到，新的是支持响应式编程的，而老的只能基于同步，这是一个巨大的提升。

为了简化大家的使用，我们需要实现一个**代码生成器，自动基于老的写法，生成新的代码**。

需要考虑的是，老的我们实现了一个自己的`com.ciicgat.api.core.JacksonDecoder`，来处理ApiResponse形式的返回结果，而这个会与新的不兼容。两个方案：

1. 让老版本框架，识别请求来自新框架，如果是新框架，那么将返回的code、msg、data的json形成，变为data。code和msg放在返回的header里。
2. 新版本框架兼容ApiResponse形式

我们还需要适配关爱通服务发现规范。



## 目标

大的目标

1. 全面兼容Springboot3.0和java17
2. 趁机解决很多历史遗留问题

## 范围

### 依赖

1. jdk使用java17
2. springboot升级到3.0
3. javax.servlet升级到jakarta.servlet
4. javax.validation升级到jakarta.validation

### 新增模块

1. 新声明式httpclient sdk
2. 新声明式httpclient代码生成器

### 升级优化

1. 支持响应式编程，包括所有server和所有client端。
2. springfox替换为springdoc
3. HttpClientHelper底层基于netty httpclient，移除okhttpclient依赖
4. 原来`com.ciicgat.sdk`切换到`com.ciicgat.grus`
5. GrusMybatisAutoConfiguration通过继承MybatisAutoConfiguration实现读写分离的功能



### 删除模块

1. velocity以及starter
2. grus-feign以及starter
3. grus-validator以及starter
